# Project Plan: The Mind Museum

**Target Audience:** Ages 10–15
**Goal:** Deliver a lightweight, locally runnable MVP containing 6 cognitively demanding games focusing on logic, spatial awareness, and typing muscle memory.
**Tech Stack:** Angular 17+ (Frontend & Server via SSR), `better-sqlite3` (Database), Phaser.js & Three.js (Game Engines).

---

## 1. System Architecture (Angular Full-Stack)

This project utilizes a monolithic architecture where a single Angular repository handles both the server-rendered UI and the backend API routes using Express.

*   **The Backend (API Layer):** The default `server.ts` generated by Angular SSR is extended to include custom `/api/*` routes.
*   **The Database Engine:** `better-sqlite3` operates synchronously on the Node.js server, querying a local `.db` file for blazing-fast local performance.
*   **The Frontend (Client Layer):** Standard UI elements (Museum Hub, Leaderboards) are server-rendered for fast loading. Game canvases are strictly delayed until hydration on the browser to prevent Node crashes.

### Architecture Visualization
```text
[ Browser Request ] 
       │
       ▼
[ Angular Express Server (server.ts) ] 
       ├── Route: /api/telemetry ---> [ better-sqlite3 ] ---> [ mind_museum.db ]
       └── Route: /* (Page Load) ---> [ Angular SSR Engine ] ---> HTML Response
```

## 2. Database Schema

The local `mind_museum.db` file will track player profiles, game sessions, and detailed cognitive telemetry.

| Table | Columns | Purpose |
| :--- | :--- | :--- |
| **`players`** | `id` (PK), `username`, `created_at` | Global user accounts for the platform. |
| **`sessions`** | `id` (PK), `player_id` (FK), `game_id`, `duration_ms` | Tracks overall engagement per game wing. |
| **`telemetry`** | `id` (PK), `session_id`, `metric_type`, `value`, `payload` (JSON) | Stores game-specific data (e.g., `metric_type='WPM', value=85`). |
| **`logic_errors`** | `id` (PK), `session_id`, `gate_type`, `failed_state` | Granular tracking for bottlenecks in logic/systems games. |

## 3. The MVP Game Roster

1. **Terminal Velocity (Cybernetics Wing):** A typing defense game testing keystroke muscle memory, syntax fluency, and reaction speed. Built with native Angular + HTML5 Canvas.
2. **Node Network (Systems Wing):** A grid-based puzzle focusing on network topology and resource routing. Built with Phaser.js.
3. **Logic Gate Defender (Circuitry Wing):** A tower defense game requiring Boolean logic (AND, OR, NOT) to wire towers. Built with Phaser.js.
4. **Contraption Crafter (Mechanics Wing):** A sandbox for building Rube Goldberg machines, testing physics and cause-and-effect. Built with Phaser + Matter.js.
5. **Algorithmic Alchemist (Logic Wing):** A procedural sequencing game using loops and conditionals to synthesize elements. Built with Angular Drag-and-Drop + Canvas.
6. **Optic Architect (Dimensions Wing):** An isometric 3D puzzle testing mental rotation and perspective alignment. Built with Three.js.

## 4. Development Roadmap (10-Week MVP)

### Phase 1: API & Server Foundation (Weeks 1-2)
*   **Setup:** Generate workspace (`ng new mind-museum --ssr`). Install `better-sqlite3`.
*   **Extend Server:** Modify `server.ts` to instantiate the SQLite connection and expose `/api/` endpoints.
*   **Museum Hub:** Build the Angular UI for the lobby, profile selector, and game dashboard. Connect to API via `HttpClient`.

### Phase 2: Native Angular Games (Weeks 3-4)
*   **Game 1 (Terminal Velocity):** Implement global keystroke listeners (`HostListener`) and falling word mechanics. Log WPM/accuracy to `/api/telemetry`.
*   **Game 5 (Algorithmic Alchemist):** Build the visual drag-and-drop scripting interface and the canvas animation executor.

### Phase 3: The Phaser Integration (Weeks 5-7)
*   **Client Bridge:** Implement `isPlatformBrowser` checks to ensure Phaser does not run during server-side rendering.
*   **Game 2 (Node Network):** Build grid routing and packet mechanics.
*   **Game 3 (Logic Gate Defender):** Build Boolean logic engine and enemy spawning.
*   **Game 4 (Contraption Crafter):** Integrate physics engine (Matter.js) and inventory placement.

### Phase 4: Spatial 3D (Week 8)
*   **Game 6 (Optic Architect):** Setup Three.js. Implement orthographic camera and raycasting for perspective alignment mechanics.

### Phase 5: Analytics & Polish (Weeks 9-10)
*   **Analytics Dashboard:** Build the "Progress Wing" visualizing cognitive stats pulled from the SQLite database.
*   **Deployment:** Package as a single Node.js build for easy local or VPS deployment.

## 5. Crucial Integration Pattern: Angular SSR + Games

To prevent `window is not defined` errors during server-rendering, game engines must be dynamically loaded on the client side only.

**Client Game Component (`game-wrapper.component.ts`):**
```typescript
import { Component, ElementRef, ViewChild, PLATFORM_ID, Inject, AfterViewInit } from '@angular/core';
import { isPlatformBrowser } from '@angular/common';

@Component({
  selector: 'app-game-canvas',
  template: `<div #gameContainer></div>`,
  standalone: true
})
export class GameCanvasComponent implements AfterViewInit {
  @ViewChild('gameContainer') container!: ElementRef;

  constructor(@Inject(PLATFORM_ID) private platformId: Object) {}

  async ngAfterViewInit() {
    // Critical: Prevents Phaser from running on the Node server
    if (isPlatformBrowser(this.platformId)) {
      const Phaser = await import('phaser');
      
      new Phaser.Game({
        parent: this.container.nativeElement,
        type: Phaser.AUTO,
        width: 800,
        height: 600,
        scene: { /* Game Logic */ }
      });
    }
  }
}
```
